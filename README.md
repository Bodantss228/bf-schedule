# Расписание БФ ПНИПУ

Рабочее ядро: Next.js App Router, TypeScript, Tailwind CSS, компоненты shadcn/ui на Radix, Drizzle и PostgreSQL. Источник — настоящий ASP-отчёт БФ ПНИПУ, а не выдуманные данные.

## Локальный запуск без регистрации

Нужен Node.js 22.

```sh
npm ci
npm run sync
npm run dev
```

Откройте http://localhost:3000. Без DATABASE_URL парсер сохраняет настоящие данные в `data/snapshot.json`, а приложение читает их. Снимок исключён из Git. При первой синхронизации запрашиваются все группы последовательно; это занимает несколько минут. Для быстрой проверки одной группы в PowerShell: `$env:SYNC_GROUP='ПОВТ-24д'; npm run sync`. Удалите переменную перед полной синхронизацией: `Remove-Item Env:SYNC_GROUP`. Расписание преподавателей и подписка для них будут полными только после загрузки всех групп.

## Публикация: Vercel + Neon + GitHub Actions

1. Создайте бесплатную PostgreSQL-базу в Neon. Скопируйте pooled connection string с SSL. Supabase тоже подходит: используйте серверный pooler, пароль БД, не публичный anon key.
2. Скопируйте `.env.example` в `.env.local` и заполните DATABASE_URL, либо задайте переменную в терминале. Выполните `npm run db:migrate` для создания таблиц и учёта версий схемы. Схема находится в `lib/schema.ts`, SQL-миграции — в `drizzle/`. `db:push` оставлен для локального прототипирования, на опубликованной базе используйте миграции.
3. Выполните `npm run sync` с DATABASE_URL. Убедитесь, что все группы обновлены.
4. Загрузите проект в свой GitHub-репозиторий. В Settings → Secrets and variables → Actions добавьте секрет DATABASE_URL.
5. Импортируйте репозиторий в Vercel, framework Next.js. Добавьте DATABASE_URL в серверные Environment Variables и запустите deploy. Никогда не используйте NEXT_PUBLIC_DATABASE_URL.
6. В GitHub Actions вручную запустите Update schedule. Затем он будет запускаться каждые 3 часа (cron в UTC). Vercel Cron не нужен. На Vercel локальный JSON не заменяет базу.

Бесплатные тарифы подходят для небольшого некоммерческого сервиса, но не гарантируются навсегда. GitHub может задерживать cron; у публичных неактивных репозиториев scheduled workflows отключаются после 60 дней отсутствия активности, их нужно включить снова. Проверяйте лимиты провайдеров. Neon способен засыпать между запросами: первый запрос иногда медленнее. Парсер и фронтенд не зависят от специального API этих провайдеров — можно перенести PostgreSQL и Next.js на другой хостинг. Перед запуском для большой аудитории оцените лимиты Vercel и условия Hobby.

## Как обновляются данные

- Один каталог и один POST-отчёт на группу. Преподаватели выводятся из групповых занятий.
- Windows-1251 в обе стороны, даты `dd.mm.yy`, часы `8.30`, девять колонок `tr.reportitem`. Типы ПЗ, Л/Р, ЛК; неизвестные обозначения сохраняются как есть.
- Окно синхронизации: прошлая, текущая и три следующие недели. Календарь использует скользящее окно; далёкие даты не обещаются как загруженные.
- Таймаут 25 секунд, до четырёх попыток, exponential backoff и небольшая случайная задержка. Проверяются заголовки отчёта, выбранная группа, период и каждая строка.
- После трёх неудачных групп подряд синхронизация останавливается с ошибкой до следующего запуска, чтобы не расходовать минуты Actions и не нагружать неработающий источник.
- Для каждой группы одна транзакция: новые записи вставляются, неизменившиеся сохраняют ID и updated_at, исчезнувшие в успешно загруженном периоде удаляются. ID — хеш всех значимых полей, поэтому корректно сохраняются одновременно идущие занятия разных подгрупп, если они различаются в отчёте. Полностью одинаковые строки дедуплицируются. Изменённое занятие в iCal заменяется новым событием.
- Валидный пустой отчёт означает отсутствие/отмену занятий. Ошибка сети, чужой отчёт или изменившаяся HTML-структура не очищают расписание. Данные других групп могут обновиться, workflow завершится ошибкой при частичном сбое. Последняя успешная проверка учитывается отдельно от updated_at пары.
- Для преподавателя полнота и свежесть проверяются по всем группам — это консервативно, зато не скрывает возможные пропуски. Подписка возвращает 503 до завершения первичной синхронизации, чтобы календарь не принял неполные данные за отмены.
- PostgreSQL хранит до 90 дней прошедших занятий. Выборки индексированы по группе/дате и преподавателю/дате. API имеет кратковременный CDN-кеш.
- При смене учебного года исчезнувшие из каталога группы помечаются неактивными. Они не мешают полноте расписания преподавателей; прошлые записи сохраняются до плановой очистки.

## Возможности

Группы/преподаватели, поиск, избранное и раздельный последний выбор в LocalStorage, неделя/дата, подсветка текущей пары и оставшееся время в UTC+5, подписка iCalendar. Данные выбранной недели сохраняются в браузере и показываются при ошибке сети. Манифест позволяет подготовить установку на главный экран; полное офлайн-приложение и push-уведомления в этот MVP не входят.

Подписка: `/api/calendar?mode=group&id=…` либо `mode=teacher`. В Apple Calendar добавьте подписной календарь по скопированному HTTPS-URL; в Google Calendar — «Другие календари → По URL» в веб-версии. Приложение календаря самостоятельно определяет частоту обновлений, моментального обновления каждые 3 часа гарантировать нельзя. Скачанный .ics — разовый импорт.

API: `/api/catalog`, `/api/schedule?mode=group&id=…&from=YYYY-MM-DD&to=YYYY-MM-DD`. Ошибки имеют статусы 400/404/503. Пустой результат вне загруженного периода отображается как отсутствие данных, не как выходной.

## Проверки

```sh
npm test
npm run typecheck
npm run build
```

Тесты проверяют ASP-формат, кодировку, отмены/повреждённые отчёты, стабильность ID, UTC+5, валидацию запросов, retry и UTF-8 iCalendar. Отдельный тест запускает PostgreSQL в памяти через PGlite: проверяет SQL-миграции, повторные вставки, замены, отмены, изоляцию групп и откат транзакции. Для живой проверки источника выполните sync. Для проверки подключения облачного PostgreSQL нужны ваши реальные реквизиты; тесты не подключаются к чужим базам.
